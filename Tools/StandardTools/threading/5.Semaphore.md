`Semaphore`（信号量）是 `threading` 里仅次于 `Lock`、`Event` 的重要同步工具。

如果说：

```text
Lock      = 最多允许 1 个线程进入
Semaphore = 最多允许 N 个线程进入
```

那么 `Semaphore` 本质上就是：

> **带计数器的 Lock。**

---

# 1. 为什么需要 Semaphore

假设你有一个数据库连接池：

```text
连接1
连接2
连接3
```

最多只能同时使用 3 个连接。

如果来了 100 个线程：

```text
Thread1
Thread2
...
Thread100
```

你希望：

```text
同时最多 3 个线程访问数据库
其他线程等待
```

这就是 Semaphore 的典型场景。

---

# 2. Lock 与 Semaphore 的区别

### Lock

```python
lock = threading.Lock()
```

状态只有：

```text
锁着
没锁
```

同时只能：

```text
1个线程
```

进入。

---

### Semaphore

```python
sem = threading.Semaphore(3)
```

表示：

```text
最多允许3个线程同时进入
```

---

形象理解：

### Lock

```text
厕所
┌───┐
│ 1 │
└───┘
```

只能进一个人。

---

### Semaphore(3)

```text
停车场
┌───┬───┬───┐
│ 1 │ 2 │ 3 │
└───┴───┴───┘
```

三个车位。

---

# 3. 创建 Semaphore

```python
import threading

sem = threading.Semaphore(3)
```

参数：

```python
Semaphore(value)
```

这里：

```text
value = 3
```

表示：

```text
剩余许可证 = 3
```

---

# 4. acquire()

获取许可证

```python
sem.acquire()
```

流程：

```text
许可证 > 0
    ↓
减1
    ↓
继续执行
```

---

例如：

```python
sem = threading.Semaphore(3)
```

初始：

```text
3
```

线程A：

```python
sem.acquire()
```

变成：

```text
2
```

---

线程B：

```python
sem.acquire()
```

变成：

```text
1
```

---

线程C：

```python
sem.acquire()
```

变成：

```text
0
```

---

线程D：

```python
sem.acquire()
```

此时：

```text
没许可证了
```

线程D阻塞等待。

---

# 5. release()

释放许可证

```python
sem.release()
```

例如：

```text
当前许可证 = 0
```

线程A结束：

```python
sem.release()
```

变成：

```text
1
```

于是：

```text
线程D被唤醒
```

拿到许可证继续执行。

---

# 6. 最经典例子

限制并发数。

```python
import threading
import time

sem = threading.Semaphore(3)
```

---

工作线程：

```python
def worker(i):

    with sem:

        print(f"{i} start")

        time.sleep(3)

        print(f"{i} end")
```

---

启动：

```python
for i in range(10):
    threading.Thread(
        target=worker,
        args=(i,)
    ).start()
```

---

输出类似：

```text
0 start
1 start
2 start

(3秒)

0 end
1 end
2 end

3 start
4 start
5 start
...
```

永远只有：

```text
3个线程同时运行
```

---

# 7. with Semaphore

和 Lock 一样。

推荐：

```python
with sem:
    do_work()
```

等价：

```python
sem.acquire()

try:
    do_work()
finally:
    sem.release()
```

---

项目里几乎都写：

```python
with sem:
```

---

# 8. acquire(blocking=False)

不等待。

```python
ok = sem.acquire(blocking=False)
```

返回：

```python
True
```

获得许可证。

或者：

```python
False
```

没有许可证。

---

例如：

```python
if sem.acquire(False):
    try:
        work()
    finally:
        sem.release()
else:
    print("资源已满")
```

---

# 9. acquire(timeout)

超时等待。

```python
sem.acquire(timeout=5)
```

意思：

```text
最多等5秒
```

返回：

```python
True
```

获得许可证。

或者：

```python
False
```

超时。

# 10. Semaphore 内部原理

可以把它想象成：

```python
count = 3
```

---

acquire：

```python
if count > 0:
    count -= 1
else:
    wait()
```

---

release：

```python
count += 1

notify()
```

---

当然源码里会用：

```python
Condition
Lock
```

保证线程安全。

# 14. Semaphore vs Queue

很多人纠结：

什么时候用 Queue？

什么时候用 Semaphore？

---

### Queue

解决：

```text
任务传递
```

例如：

```text
Producer
   ↓
 Queue
   ↓
Consumer
```

---

### Semaphore

解决：

```text
资源数量限制
```

例如：

```text
数据库连接池

连接1
连接2
连接3
```

---

一句话：

```text
Queue 管任务
Semaphore 管资源
```

# 15. BoundedSemaphore

还有一个特殊版本：

```python
threading.BoundedSemaphore
```

---

普通 Semaphore：

```python
sem = threading.Semaphore(3)
```

可以：

```python
sem.release()
sem.release()
sem.release()
```

无限加。

变成：

```text
6
7
8
9
...
```

---

而：

```python
sem = threading.BoundedSemaphore(3)
```

最大值固定：

```text
3
```

---

如果：

```python
sem.release()
```

超过上限：

```python
ValueError
```

---

适合发现代码 Bug。

# 16. Semaphore 和 Lock 的关系

其实：

```python
threading.Lock()
```

可以理解成：

```python

```

---

区别：

Lock：

```text
0
1
```

只能二选一。

---

Semaphore：

```text
0~N
```

允许多个许可证。

# 18. 最核心的理解

记住这个模型就够了：

```text
Semaphore(N)

=N张许可证
```

线程执行前：

```text
拿许可证
```

线程结束后：

```text
归还许可证
```

当许可证用完：

```text
等待
```

直到有人归还。

---

所以：

```text
Lock
 = 1张许可证

Semaphore(5)
 = 5张许可证

Semaphore(100)
 = 100张许可证
```

在工程里，`Semaphore` 最常见的用途几乎都是：

1. 限制数据库连接数
2. 限制 HTTP 请求并发数
3. 限制爬虫抓取并发数
4. 限制同时执行的任务数量

它本质上是一个**并发限流器（Concurrency Limiter）**。
