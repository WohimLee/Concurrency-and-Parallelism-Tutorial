`Lock` 是 `threading` 里面最核心的同步工具。

如果说：

```text
Thread = 开线程
Event = 发通知
Lock = 防止多个线程同时修改同一份数据
```

那么几乎所有线程安全问题最终都会回到 `Lock`。

---

# 1. 为什么需要 Lock

先看一个简单例子：

```python
count = 0

def add():
    global count

    for _ in range(100000):
        count += 1
```

启动两个线程：

```python
t1 = Thread(target=add)
t2 = Thread(target=add)

t1.start()
t2.start()

t1.join()
t2.join()

print(count)
```

你可能觉得：

```text
100000 + 100000 = 200000
```

实际上经常会出现：

```text
173821
192354
198762
```

各种结果都有可能。

---

# 2. 为什么会出错

很多人以为：

```python
count += 1
```

是一个动作。

实际上不是。

Python 字节码层面大致是：

```text
读取 count
    ↓
计算 count + 1
    ↓
写回 count
```

即：

```text
Thread A                Thread B

读取 count=10
                         读取 count=10

计算11
                         计算11

写回11
                         写回11
```

结果：

```text
应该变成12
实际变成11
```

一次加法丢失了。

这叫：

> Race Condition（竞态条件）

---

# 3. Lock 的本质

Lock 可以理解成厕所门锁。

```text
线程A
  ↓
拿到锁
  ↓
进入厕所

线程B
  ↓
发现门锁着
  ↓
等待
```

只有一个线程能进去。

---

# 4. 创建 Lock

```python
import threading

lock = threading.Lock()
```

初始状态：

```text
未上锁
```

---

# 5. acquire()

获取锁

```python
lock.acquire()
```

如果锁空闲：

```text
成功获得锁
继续执行
```

如果锁已被占用：

```text
阻塞等待
```

---

例如：

```python
lock.acquire()

print("working")

lock.release()
```

---

# 6. release()

释放锁

```python
lock.release()
```

释放后：

```text
其他线程可以获取
```

---

# 7. 最基本写法

```python
lock.acquire()

try:
    count += 1

finally:
    lock.release()
```

为什么用 finally？

因为：

```python
count += 1

raise Exception()
```

如果异常发生：

```python
release()
```

可能执行不到。

整个程序就死锁了。

---

# 8. 推荐写法：with

几乎所有项目都这样写：

```python
with lock:
    count += 1
```

等价于：

```python
lock.acquire()

try:
    count += 1

finally:
    lock.release()
```

所以：

```python
with lock:
```

一定要熟练。

---

# 9. 修复计数器问题

```python
count = 0
lock = threading.Lock()

def add():
    global count

    for _ in range(100000):

        with lock:
            count += 1
```

结果：

```text
200000
```

永远正确。

---

# 10. 临界区（Critical Section）

Lock 保护的代码区域叫：

> 临界区（Critical Section）

例如：

```python
with lock:
    count += 1
```

这里就是临界区。

---

原则：

```text
临界区越小越好
```

不要：

```python
with lock:

    download_file()

    process_data()

    save_db()
```

这样锁持有时间太长。

---

更合理：

```python
data = download_file()

result = process_data(data)

with lock:
    save_db(result)
```

---

# 11. acquire(blocking=False)

默认：

```python
lock.acquire()
```

等价：

```python
lock.acquire(blocking=True)
```

拿不到锁就等。

---

也可以：

```python
lock.acquire(blocking=False)
```

拿不到立即返回。

---

例子：

```python
ok = lock.acquire(blocking=False)

if ok:
    try:
        work()
    finally:
        lock.release()
else:
    print("锁被占用")
```

返回：

```python
True
False
```

---

# 12. acquire(timeout=)

超时等待。

```python
lock.acquire(timeout=5)
```

意思：

```text
最多等5秒
```

返回：

```python
True
```

获得锁

或：

```python
False
```

超时

---

# 13. 死锁（Deadlock）

这是 Lock 最危险的问题。

---

例子：

```python
lock.acquire()

lock.acquire()
```

第二次：

```text
永远等待
```

因为：

```text
自己拿着锁
自己又等自己释放
```

程序卡死。

---

例如：

```python
lock = threading.Lock()

def test():

    lock.acquire()

    lock.acquire()
```

直接死锁。

---

# 14. RLock 为什么存在

解决刚才的问题。

```python
lock = threading.RLock()
```

R = Reentrant

可重入锁

---

同一线程：

```python
lock.acquire()

lock.acquire()

lock.acquire()
```

允许。

---

对应释放：

```python
lock.release()
lock.release()
lock.release()
```

次数必须匹配。

---

典型场景：

```python
class Cache:

    def update(self):

        with self.lock:
            self.refresh()

    def refresh(self):

        with self.lock:
            ...
```

普通 Lock 会死锁。

RLock 不会。

---

# 15. 多把锁导致的死锁

更常见的是：

```python
lockA
lockB
```

线程1：

```python
lockA.acquire()

lockB.acquire()
```

线程2：

```python
lockB.acquire()

lockA.acquire()
```

可能出现：

```text
Thread1 持有A 等B

Thread2 持有B 等A
```

双方永远等待。

---

这叫经典死锁：

```text
A 等 B
B 等 A
```

---

解决办法：

统一顺序。

例如规定：

```text
永远先拿A
再拿B
```

# 16. Lock 保护什么

最常见：

---

## 共享变量

```python
count += 1
```

---

## 字典

```python
cache[key] = value
```

---

## 集合

```python
users.add(uid)
```

---

## 文件

```python
with open("log.txt", "a") as f:
    f.write(msg)
```

多个线程同时写文件可能混乱。

---

## 数据库连接

```python
conn.execute(...)
```

很多连接对象不是线程安全的。

# 17. Lock 和 GIL 的关系

这是面试高频。

很多人以为：

```text
有 GIL
不需要 Lock
```

错。

---

GIL 保证：

```text
同一时刻只有一个线程执行 Python 字节码
```

但不保证：

```text
多个操作组成的逻辑是原子的
```

例如：

```python
count += 1
```

仍然可能出现竞态。

所以：

```text
GIL ≠ Lock
```

# 19. Lock 的一句话理解

可以把 `Lock` 看成：

```text
一个只能同时容纳一个线程进入的房间
```

```text
acquire()
    ↓
关门

临界区
    ↓

release()
    ↓
开门
```

它解决的核心问题只有一个：

> 防止多个线程同时操作共享资源，从而避免竞态条件（Race Condition）。

学习顺序建议是：

```text
Thread
 ↓
Lock
 ↓
RLock
 ↓
Event
 ↓
Condition
 ↓
Semaphore
```

因为理解了 `Lock`，后面的同步工具本质上都是在它的基础上扩展出来的。
